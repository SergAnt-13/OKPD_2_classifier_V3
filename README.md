# Академическое сравнение подходов

### Сравнение с baseline (TF‑IDF + kNN)

### backend/tests/compare_tfidf_knn.py

**Методика:**
- TF‑IDF + kNN: векторизация стеммированных названий справочника ОКПД‑2 с символьными n‑граммами (3–5), поиск 10 ближайших соседей по косинусному расстоянию.
- Наш чемпион: `bge‑m3‑frozen‑3epoch` (дообученный BGE‑M3 со стеммингом).
- Оценка на всей экспертной выборке (1475 примеров).

#### Основные метрики

| Метрика | TF‑IDF + kNN | BGE‑M3 (frozen‑3epoch) | Прирост |
|---------|--------------|------------------------|---------|
| Recall@1 | 0.1044 | **0.5261** | ×5.0 |
| Recall@5 | 0.2034 | **0.7864** | ×3.9 |
| Recall@10 | 0.2542 | **0.8664** | ×3.4 |
| MRR | 0.1461 | **0.6455** | ×4.4 |
| NDCG@10 | 0.1716 | **0.6961** | ×4.1 |

**Вывод:** TF‑IDF даже с символьными n‑граммами не способен уловить семантику сокращений и сленга. BGE‑M3 превосходит его в 3.4–5.0 раз по всем основным метрикам, обеспечивая правильный код в топ‑10 для 86.6% товаров.

#### Tail breakdown (Recall@10 по частоте классов)

| Группа классов (число примеров в золоте) | TF‑IDF + kNN | BGE‑M3 (frozen‑3epoch) | Support |
|------------------------------------------|--------------|------------------------|---------|
| 1 (редчайшие) | 0.4651 | **0.6977** | 43 |
| 2–5 (редкие) | 0.4132 | **0.7246** | 167 |
| 6+ (частые) | 0.2261 | **0.8909** | 1265 |

**Вывод:** BGE‑M3 одинаково сильна на частых и редких классах, в то время как TF‑IDF полностью проваливается на массовых категориях. Это доказывает устойчивость retrieval‑first архитектуры к long‑tail распределению.

#### Calibration curve (BGE‑M3, топ‑1 скор vs actual recall)

| Диапазон top‑1 скора | Actual Recall (доля правильных) | Число запросов |
|----------------------|----------------------------------|----------------|
| 0.30–0.50 | 0.108 | 102 |
| 0.50–0.70 | 0.506 | 997 |
| 0.70–0.90 | 0.694 | 376 |

**Вывод:** скор модели хорошо откалиброван: в диапазоне 0.50–0.70 модель права в 50.6% случаев, в диапазоне 0.70–0.90 — в 69.4%. Это позволяет использовать пороговые правила в Decision Engine с предсказуемой точностью (например, при пороге 0.7 точность AUTO составляет ~70%).

#### Дополнительные метрики BGE‑M3

- **Mean Margin** (отрыв первого кандидата от второго): 0.0732
- **Median Margin**: 0.0394

Низкий медианный margin подтверждает необходимость режима REVIEW для случаев с малым отрывом.

**Общий вывод:** retrieval‑first с дообученным би‑энкодером и стеммингом радикально превосходит классический TF‑IDF, сохраняя высокое качество на всём спектре частот классов и предоставляя хорошо откалиброванные скоры для автоматизации принятия решений.

### Сравнение BERTA с RuBERT (V2)

### backend/tests/evaluate_berta_classifier.py

**Результаты классификации на экспертной выборке:**

| Модель | Число классов | Accuracy | Macro F1 | Weighted F1 | Уникальных предсказанных классов | Покрытие классов экспертной выборки  |
|--------|--------------|----------|----------|-------------|----------------------------------|--------------------------------------|
| RuBERT (V2) | 55 | **0.81** | 0.46 | 0.74 | – | ~60% (только частые)                 |
| BERTA (V3) | ~1000 | **0.8352** | 0.5923 | 0.7977 | 78 | 100% (все классы экспертной выборки) |

**Резолюция:**
- BERTA превосходит RuBERT по всем метрикам, несмотря на работу с порядком большим числом классов.
- Weighted F1 0.798 против 0.74 у RuBERT говорит о лучшем качестве на частых классах.
- Macro F1 0.592 (против 0.46) — значительно лучшая работа на миноритарных классах.
- BERTA предсказала всего 78 уникальных классов — модель консервативна и не «фантазирует» на редкие классы, что идеально для роли верификатора: она либо уверенно подтверждает частый класс, либо молчит.
- RuBERT был бесполезен для «хвоста» из 19k кодов. BERTA покрывает все классы экспертной выборки, а благодаря retrieval‑first архитектуре система обслуживает весь справочник ОКПД‑2.
- BERTA‑классификатор уступает retrieval (R@10=0.88), поэтому используется как вспомогательный инструмент для повышения точности в режиме AUTO.

**Вывод:** Переход от RuBERT к retrieval‑first с BERTA‑верификацией позволил преодолеть ограничение по числу классов и обеспечить полное покрытие справочника ОКПД‑2, превзойдя RuBERT по качеству на всех типах классов.

### Анализ потенциала автоматизации (через calibration curve)

### backend/tests/evaluate_engine_thresholds.py

**Методика:** Decision Engine прогнан на всей золотой выборке с варьированием `auto_threshold` (при фиксированных `review_threshold=0.3`, `margin_threshold=0.05`, `ood_threshold=0.2`).

**Результаты:**

| auto_threshold | Доля AUTO | Точность в AUTO |
|---------------|-----------|-----------------|
| 0.35–0.65 | 51.5% | 87.1% |
| 0.70 | 49.0% | 88.5% |
| 0.75 | 46.2% | 91.1% |
| **0.80** | **43.1%** | **95.0%** |

**Выводы:**
- При пороге 0.80 система автоматизирует **43% экспертных записей с точностью 95%** — это готовый к внедрению уровень надёжности.
- Порог 0.75 даёт **46% AUTO с точностью 91%** — компромисс для менее критичных сценариев.
- На промышленных данных доля AUTO ожидается ниже (30-40%)
- REVIEW и MANUAL покрывают оставшиеся запросы, при этом REVIEW требует лишь выбора из 2–3 кандидатов, что значительно быстрее полного ручного поиска.
